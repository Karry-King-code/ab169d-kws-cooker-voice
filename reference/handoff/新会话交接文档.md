## 4. 重要决策与原因（哪些不要随便改）

| 决策 | 原因 | 不要动 |
|---|---|---|
| **`UART0_PRINTF_SEL = PRINTF_PA8`** | SOP8 pin4=PA7/8/9 同脚，printf 用 PA8（J4 pin4）。绿灯(PA7)失效是已知代价 | 别改 PA3(DAC冲突)/PA2(烧录冲突) |
| **printf 波特率 1500000** | bsp_uart.c: `#if MIC_ESBC_PROC_EN udet_init(500000) #else udet_init(1500000)`，MIC_ESBC_PROC_EN=0 | 接调试串口用 1.5M |
| **DAC_EN=1 + WARNING_TONE_EN=1 + WARNING_MP3_PLAY=1** | 开音频通路 | 关掉就没播报 |
| **FLASH_SIZE=512K / FLASH_CODE_SIZE=292K** | 43条压缩MP3打进res后 dcf=473KB < 496K 上限 | 别改大 |
| **授权码 3CC9B441** | 加密狗只认这个 | 换其他烧不进 |
| **KWS 库用 634** | 和 v2.0.3 配对 | 别混 v4.0.6 的库 |
| **43条回应语 16k/8kbps 压缩** | 420KB 装不下，压缩到 93.5KB | 音质差但用户接受，最后统一处理 |
| **命令→回应语 = top+2** | 词表/Excel/res 顺序对齐 | 别改映射，除非换词库 |

## 4. 重要决策与原因（哪些不要随便改）

| 决策 | 原因 | 不要动 |
|---|---|---|
| **`UART0_PRINTF_SEL = PRINTF_PA8`** | SOP8 pin6 = PA1/2/3 同脚，printf 在 PA3 会和 DAC(PA3) 抢脚导致 boot 崩 | 别改回 PA3（除非你专门解决冲突） |
| **printf 在 PA8 后绿灯(PA7)失效** | pin4 = PA7/8/9 同脚，printf 占了 pin4 | 这是已知代价，别奇怪绿灯不闪 |
| **DAC_EN=1 + WARNING_TONE_EN=1 + WARNING_MP3_PLAY=1** | 开音频通路 | 关掉就没播报 |
| **FLASH_SIZE=512K / FLASH_CODE_SIZE=288K** | 芯片 AB169D 是 512KB，288K 容纳音频代码 | 别改小（会溢出） |
| **xcfg 提示音音量默认 6→12** | 音量太小 | 已在 xcfg.xm 改好 |
| **bsp_audio.c ASR 路径 ADC2DAC_EN→0** | 麦克风→喇叭监视会持续放噪声 | 别恢复（否则噪声回来） |
| **sound_res.c 播放前 dac_spr_set(16k)** | MP3 是 16kHz，DAC 率要匹配 | 别删 |
| **授权码 3CC9B441** | 你的加密狗只认这个 | 换其他授权码烧不进 |
| **KWS 库用 634（v3.1.0/180K）** | 和 v2.0.3 配对，识别已验证 | 别混入 v4.0.6 的 190K 库（跨代际不稳定） |

## 6. 已知问题、坑、注意事项

### 🔴 当前主问题：播报音质差（沙哑 + 噪声 + 小声）
**已做**：去 ADC2DAC 监视、DAC 设 16k、音量 12 → **用户反馈仍差很多（调最大声/降噪最大也不行）**

**尚未排查的方向**（新会话从这里继续）：
1. **MP3 编码质量问题**：当前 32kbps mono 16kHz（lameenc quality 2）——码率偏低。**重新编码更高质量**（如 64kbps 或 44.1kHz 转 16k）对比
2. **DAC 采样率/格式**：确认 mp3 解码输出和 DAC 实际配置一致（dac_spr_set 是否真的生效、解码器内部采样率）
3. **8002 功放增益**：R20/R21 反馈电阻决定增益（~15 倍），板上是否合适
4. **飞线质量**：接触不良会导致噪声/衰减（夹牢 + 用好的杜邦线）
5. **电源噪声**：USB 供电不稳 → 音频噪声；试试独立供电
6. **试参考工程的 ESBC 音质**：参考工程 kaiji.esbc 音质如何？如果 ESBC 清晰 → 换 ESBC 方案（而不是 MP3）

### 🟡 其他坑
- **SOP8 pin6 = PA1/2/3 同一个物理脚**：DAC(PA3)/调试(PA2)/MICBIAS(PA1) 三抢一——设计产品板时 PA3 必须物理接 8002
- **飞线接触不良 = "一直没声音"的元凶**（花了很久才用万用表定位）
- **KWS 库 634 不能混进 v4.0.6 框架**（跨代际，运行时异常滴答声/LED 乱跳）
- **参考工程授权码 0x68854D8F 与我们的加密狗不匹配**（已改 3CC9B441 才能烧）
- **参考工程 260KB 装不进 169C（256KB）**，只能跑 512KB 的 169D
- **资源系统 `#loadresdir` 的 `#` 是 bug**（应为 `loadresdir`）
- **ALWAYS 备份/提交**：guardrails 要求改前确认、改后验证

4. **产品板**：客户按 AB169D 出图（已确认），接线方案（PA3=DAC 必须接通 8002）

## 附：重要历史结论（一句话版）

- **为什么一直没声**：printf(PA3) 和 DAC(PA3) 抢 pin6 崩 + 飞线接触不良，两层坑互相掩盖

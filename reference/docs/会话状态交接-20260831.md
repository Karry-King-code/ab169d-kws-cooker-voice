## 3. 正在进行的:火力档位识别调优(未完成!)

### 问题
8 个"火力调整为X档"词(词表 index 2~8、19)几乎同音只差末字,KWS 近音混淆严重:
- 说"二档"→常识别成六/五/八档;说"五档"→识别成别的
- 预约二小时类似但已修好(offset+800,邻居全素人,一个加分即翻身)
- 文件内容全部核实过没错(用户听音确认),是**识别**问题,不是资源问题

### 已试且失败(教训,别再重复)
| 轮次 | 做法 | 结果 |
|---|---|---|
| 1 | 给被说错的词加分(3/4/5/19 +400) | ❌ 五/八是天然"霸王词",加分反助抢答 |
| 2 | 二档+600 压六档 | ⚠️ 六档好点,五/八又冒 |
| 3 | 压五/八(-300),保六/四/二 | ❌ 五/二自身失灵 |
| - | HUART_PRINTF_EN=1(printf走PA10) | ❌❌ 直接死机: SDK printf模式裁剪HUART RX/IRQ路径与命令通道冲突,**此开关在本工程永远勿开** |

### 当前策略(edd3576):遥测帧 + 逻辑分析仪抓真实数据,一轮定参
- 火力 offset 全部归零(观察天然排名)
- 新增遥测帧:**未命中候选帧**发 9 字节到 PA10:
  `A5 FB | top | probL | probH | thrL | thrH | CK | FB`
  (命中帧仍走原命令帧 `A5 FA | ID | CK | FB`,两者同帧互斥)
- 开关:`config.h` `HUART_DEBUG_TELEMETRY` (正式版改 0 即消失;AD248B 解析 A5 FA 会忽略 A5 FB)
- 代码位置:bsp_asr.c 的 `if(top>=0)` 块;实现 uart_cmd.c `uart_debug_frame()`
- 抓取:逻辑分析仪接 Pin1(PA10),4562bps 8N1 解码,8 档位各说 3 遍

### 定参方法(拿到数据后)
看 FB 帧序列:某音频的候选 top 演变 + prob/thr 差值 → 给被抢词 offset 设为"刚好压过抢答词超出门槛的分数"。若 8 词天然分差太大压不平 → 升级路径:找中科蓝讯(石工)重训词库。

# AB169D 芯片手册总结（操作前必读）

> **目的**：开发/调试 AB169D 前，先读本文件了解引脚映射、外设支持——避免靠猜（实测教训：没读手册猜引脚/延时，浪费大量时间）。
> 数据源：`reference/chip/AB169C_AB169D DataSheet.pdf`、`AB16X_SDK开发手册(1).pdf`、SDK 源码（config_define.h/io_def.h）

---

## 1. 芯片关键参数

| 项 | 值 |
|---|---|
| 内核 | RISC-V RV32IMAC @160MHz（config 配 SYS_192M） |
| Flash / RAM | 512KB / 56KB+16K Cache |
| 电源 | 2~5.5V |
| GPIO | 5 个可用（SOP8） |
| 封装 | SOP8 |

## 2. SOP8 引脚复用表（核心！每个物理脚对应多个 PA，软件配哪个就是哪个）

| Pin | 复用 PA | 实测/用途 |
|---|---|---|
| Pin1 | VDD | 电源输入 |
| Pin2 | **PA10 / PA11** | J4 引出；**PA10 = HUART TX 可用**（本项目串口命令帧用 PA10 ✅） |
| Pin3 | VIO | IO 电平参考 |
| Pin4 | **PA7 / PA8 / PA9** | **实测是 PA7**（LED2/绿灯）；printf 配 PA8 发不到 pin4 |
| Pin5 | **PA4 / PA5 / PA6** | LED3/调试 J2；HUART(PA5/6) 实测收不到（疑实际是 PA4） |
| Pin6 | **PA1 / PA2 / PA3** | DAC(PA3)/烧录(PA2)/MICBIAS(PA1) 三抢一 |
| Pin7 | GND | 地 |
| Pin8 | **PA0** | MIC 输入 |

> ⚠️ **关键**：每个物理脚是"复用"（PA7/8/9 三选一等），**软件配哪个 PA，该脚就是哪个 PA**（如 pin4 配 PA7 实测有效）。**开发前必须确认实际映射，别猜**。

## 3. UART 外设支持（本项目结论）

| 外设 | TX 支持引脚 | RX 支持引脚 | 本项目结论 |
|---|---|---|---|
| **UART0** | PA3/PA8/PA2/PA12/PA14 | PA4/PA9/PA1/PA13/PA15 | 不支持 PA7（pin4）→ 本项目不可用 |
| **HUART** | **PA5/PA6/PA2/PA10/PA11** | 同 TX（半双工） | **PA10(pin2) 可用 ✅**（本项目用它，4800，2停止位） |
| 波特率 | UART0 由 `udet_init()` 设；HUART 由 `HUART_BAUD` 宏（bsp_huart.h） | | |

**本项目串口方案（已验证）**：
- **HUART 外设，PA10（pin2）**，4800bps，**2 停止位**（HUART 默认 `HSUT0CON BIT(9)`）
- 发送：`bsp_huart_putchar_data(buf, len)`
- 协议：`0xA5 0xFA | ID | 校验 | 0xFB`（校验=(0xA5+0xFA+ID)&0xFF）
- 实测：唤醒 `A5 FA 00 9F FB`、打开火锅 `A5 FA 01 A0 FB` ✅

## 4. 经验教训（重要！）

1. **开发/调试前先读本手册 + 引脚表**——避免猜引脚（本项目 pin4 实测 PA7，不是 PA8）
2. **UART0 printf 在 PA8，但 pin4 是 PA7**——所以 printf 从没发到过 pin4（调试口）
3. **延时问题**：`delay_us()` 参数不生效（bit 宽度固定）、`rdcycle` 不支持（死循环）——**不要用 GPIO bit-bang 做 UART**，用硬件 UART（HUART）
4. **接线确认**：USB-TTL/逻辑分析仪必须接对实际引脚（本项目接对 PA10 后串口立刻通）

# AB169D 电饭煲语音模块 · 整机框架教学(费曼版)

> 2026-08-31 由 Claude Code 整理,基于代码逐行核实。新会话接手必读:先读本文,再读《开发全记录》第九章。
> 类比主线:**耳朵**(MIC+SDADC)→ **脑子**(KWS+状态机)→ **嘴巴**(MP3解码+DAC+功放)。

---

## 模块 1:硬件身体

- 芯片 AB169D:RISC-V RV32IMAC @160MHz(PLL 192M),512KB flash(XIP 基址 0x11000000),56KB SRAM,SOP8
- 引脚:Pin1=PA10/11(蓝灯+HUART TX 复用,**串口实测可用**——逻辑分析仪验证,蓝灯弃用);Pin4=PA7/8(绿灯);Pin5=PA4/5(触摸按键,VBAT 碰触);Pin6=PA1/2/3 同脚(PA3=DAC→8002 功放→喇叭,PA2=烧录UTX勿占);Pin8=PA0(MIC);PA1=MIC_BIAS
- 时钟 SYS_192M(config.h:21)
- 职责边界:AB169D 只做**识别+播报+串口报信**;加热/显示/烹饪执行全归客户主控 AD248B

## 模块 2:上电启动(main.c)

```
复位 → sys_rst_init(复位原因) → bsp_sys_init(时钟/DAC上电/参数读回)
→ bsp_huart_init(HUART, PA10, 波特率4562) → sound_play_boot_welcome(播resp01"欢迎使用colorman智能产品",此时识别未启动无误唤醒风险)
→ func_run() 永不返回
```
开机语是**同步阻塞播放**(mp3_res_play 内部循环解码直到播完),开机阶段无识别任务所以安全。

## 模块 3:音频资源系统(唱片柜)

- 编码链:ttsmaker 24kHz WAV 源(reference/wav/)→ **16kHz mono 8kbps MP3** → xmaker 打包 res.bin
- res.bin 结构:偏移 0x38+(编号-1)×0x20 = 表项(addr+len),`sound_play_resp(id)` 两个指针 deref 直取,**零文件系统**
- 45 条回应语全部 16kHz/8kbps,**响度 mean -18.6dB 完全一致**(3c11c79 统一校准)
- 唤醒回应:曾内嵌 96kbps 数组,3c11c79 起改走 res(resp02, 8kbps)统一
- flash 分配:代码 274.8K(app.bin,含 KWS 权重 180K 在库内 kws_model_bin,不单独烧)+ 资源 107K + xcfg 36.3K + 头/param → dcf 469.2K / 496K 上限,余 27K

## 模块 4:采集链(耳朵)

bsp_audio.c 配置表:`{PA0, SPR_16000, 模拟增益3(≈21dB), 数字增益+18dB, DMA 768样点, asr_sdadc_process}`
→ SDADC 采 16kHz,DMA 攒 48ms 中断一次 CPU。**这个 48ms 心跳驱动一切**:识别、唤醒计时、灯、按键、烹饪轮询。

## 模块 5:KWS 脑子

```
384样点 → melspectrogram(梅尔谱) → rfft_512 → TDNN推理(权重在libkws .a内) → softmax(37词概率) → FST维特比(时序对齐防误触) → top+prob
```
- 词表 kw_string2[37]:0=你好小柯(唤醒),1~36=命令(煮饭10/煮粥12/煮面14/蒸煮16/煎炒18/打开保温35/关闭保温36)
- 每词独立阈值 WW_TRG_MODE;灵敏度微调 set_kw_offset(0,+200 唤醒)(22,+500 预约二小时防误识六小时)
- 错误检测:唤醒态+top<0+能量>4000→resp41"暂不支持";>2000→resp42"没听清"(3c11c79 阈值已调高);防抖~3秒等词说完

## 模块 6:唤醒门卫(wake_ctrl.c)

WAKE_OFF →(你好小柯)→ WAKE_FLASH(蓝绿快闪2下,半周期200ms)+播 resp02"我在请问有什么需要" → WAKE_ON(任何词刷新计时,**30秒**超时,625帧×48ms,播 resp43"我先退下了")→ WAKE_OFF
命令词仅 WAKE_ON 放行(门控)。

## 模块 7:命令分发(一传三)

唤醒态命中命令 → **①串口** uart_cmd_send(top):帧 `A5 FA | ID | 校验和 | FB`,HUART PA10 4562bps,实测逻辑分析仪抓包成功;**②播报** sound_request(top+2)(确认语);**③记录** led_ctrl(top)(灯+烹饪状态机)。诊断灯:蓝亮=识别到,播完灭。

## 模块 8:播报链路(两条铁律)

- **铁律一:说话不堵耳朵**——播报 2~3 秒不能占 48ms 中断(DMA 会溢出→识别永久失效)。解法:中断里 sound_request 只写一个 int(纸条),主循环 sound_poll 取纸条从容播。全系统一条播报通道,永不叠音。
- **铁律二:说话捂耳朵**——播报前 asr_pause_flag=true(中断里跳过识别不喂帧,但引擎不重启),播完 pause=false + **bsp_asr_restart() 重置 KWS**(流式引擎断帧后状态脏,不重置要 1.7s 才恢复,重置后立即干净)。
- mp3_res_play 同步阻塞;解码器仅 MP3/WAV(api_music.h),无 AAC/Opus。

## 模块 9:烹饪流程定时播报(2026-08-31 新增,led_yw.c cook_state_t)

```
识别煮饭10/煮粥12/煮面14/蒸煮16 → COOKING → 10s(tick_check_expire)→ sound_request(44)"已结束,进入保温状态" → WARMING → 5s → sound_request(45)"保温已结束,欢迎下次使用" → IDLE
识别打开保温35 → 直达 WARMING(5s)
任何其他命令 → 取消(可打断,命令照常执行)
```
- 计时用 SDK tick_get/tick_check_expire(绝对时间,不受播报阻塞/不依赖被 time_set_flag 门控的 led_tick);轮询挂 led_loop() 开头(不受灯 on 门控)
- 定时到点**只播报不发串口**(用户决策);加热/保温执行归 AD248B,本模块只报信

## 模块 10:主循环与内存

- 双循环并发模型:外层主循环(func_speaker while:process/message/display/**sound_poll**)干粗活;48ms 中断干细活(识别/计时/灯/键/烹饪);中间靠 volatile 便利贴(resp_pending/asr_pause_flag/cook_state)通信
- 56K RAM:MIC 缓冲 16.4K 最大头,DAC 0x900,MP3 工作区 9.5K,FFT/KWS 区;**权重不占 RAM**(flash XIP)

## 全串联时间线

```
上电 → 开机语(阻塞2.4s) → 主循环
"你好小柯" → top=0过阈 → 闪灯+播"我在"(捂耳朵2s+重置引擎) → 唤醒30s
"打开煮饭" → top=10 → 串口A5 FA 0A 8F FB给AD248B + 播resp12确认 + 状态机COOKING
10s → resp44;5s → resp45;30s无词 → resp43 → 待唤醒
```

## 音质极限结论(2026-08-31 定案)

| 手段 | 结论 |
|---|---|
| WAV | ❌ 45条=3.2MB,flash 装不下(MP3 压缩 24 倍是必需) |
| 换编码 | ❌ 芯片仅 MP3/WAV 解码器 |
| 提码率 | ❌ 8kbps 已顶格(flash 余 27K,CBR 无 9-15k 档) |
| 软件调优 | ✅ 已做完(响度-18.6dB统一/DAC/DNR) |
| **换喇叭/功放** | ✅ **唯一质变途径(产品板选型)** |
| 可选 | VBR ~11kbps 小幅提升(未做,听感增益小) |
